# ADR-006: 流式背压与零丢失语义

**状态**: Accepted
**日期**: 2026-08-31

## 背景

实时订阅场景中，消费端速度可能低于生产端（行情爆发、下游阻塞）。需要在不丢数据与不 OOM 之间取舍。

## 决策

- `BackpressureQueue` 有界队列（默认 10_000），满时抛 `BackpressureOverflow`（可恢复，advice: backoff=0.1s）
- 断线重连由 `ReconnectPolicy` 指数退避（1s 起，上限 30s，最多 10 次）
- 断线窗口的数据缺口由 `GapFiller` 用历史 K 线回填，`DeltaMerger` 去重保证单根 K 线只出现一次
- **零丢失语义**：断网 ≤30s 内重连成功则不丢增量（tests/test_stream_resilience.py 固化）

## 后果

- 消费端必须处理 `BackpressureOverflow`（或增大队列/提并发/降采样）
- GapFiller 依赖历史命令可用 —— 主站全挂时缺口标记为 unfilled 并告警

# ADR-007: Golden 自采集 + 合成衍生双轨

**状态**: Accepted
**日期**: 2026-08-31

## 背景

协议回归测试需要语料，但主站实采受时段/法律/压力约束；纯合成样本又不能证明「真实响应可解析」。

## 决策

- **实采种子**（`source: self-captured`）：盘后经 capture.py 采集，是协议事实的唯一权威来源
- **合成衍生**（`source: synthetic` + `derived_from`）：以实采样本为种子对请求维度受控变异，
  仅作为解析器回归基线，**不**声称是主站真实响应
- 清单/扩充/校验工具：`tstdx.tools.golden_expand`（manifest / expand / verify）
- 目标 ≥500 案例，sha256 全量校验（`make audit-bridges` [12] 项）

## 后果

- 回归覆盖可以离线快速扩张
- spec 收录要求：`status: stable` 的 spec 必须引用实采 golden

# ADR-008: 反馈与遥测默认关闭

**状态**: Accepted
**日期**: 2026-08-31

## 背景

匿名错误上报能改进协议覆盖，但金融数据场景用户对隐私极敏感。

## 决策

- 默认**关闭**：`TSTDX_FEEDBACK=1` 显式开启，`dry-run` 打印不发送
- 上报前强制 7 步脱敏（IP/主机名/账号代码/长串/路径/hex/元数据）
- 遥测事件环仅存内存（默认 1000 条），flush 走回调，不主动外发

## 后果

- 协议差异的群体信号变弱 —— 用 Golden 实采与 Issue 模板补偿
- 任何遥测代码缺陷都不能变成数据外泄（默认关闭是最强防线）

# ADR-009: Rust 内核可选化

**状态**: Accepted
**日期**: 2026-08-31

## 背景

纯 Python 解析在批量 K 线/全市场扫描场景有性能上限；但强制 Rust 编译会显著抬高贡献与分发门槛。

## 决策

- `tstdx_native/`（pyo3 + maturin）只承载热路径：vipdoc .day 读取、0x052D 批量解析、tdx_float
- Python 侧**运行时探测**：能 import 就用，否则回退纯 Python —— API 完全一致
- CI 中 Rust wheel 构建失败不阻塞纯 Python wheel 发版

## 后果

- 所有入口保持零硬依赖
- 双实现一致性由 golden 回放测试守护（同一 payload 两实现输出一致）

# ADR-010: Spec 驱动的协议开发流程

**状态**: Accepted
**日期**: 2026-08-31

## 背景

协议事实分散在解析器代码里，评审/回归/新人上手都困难。

## 决策

- 每个已知命令一份 YAML spec（`PROTOCOL_SPEC/<family>/`），字段布局单一事实来源
- `tools/codegen.py`：spec → 解析器骨架；`tools/spec_audit.py`：spec ↔ 账本/解析器/golden 双向校验
- 未知命令路径：Prober（限速 1 req/s + 非交易时段）或 Sniffer 被动嗅探 → `PROTOCOL_SPEC/UNKNOWN/` 草稿
- 状态机：draft → candidate → stable；stable 必须挂实采 golden + CI 门禁
- spec 变更走 PR + 双人复核

## 后果

- 协议改动可追溯、可审计
- 新命令接入成本从「逆向 + 写码」降为「填 spec + 补业务逻辑」
