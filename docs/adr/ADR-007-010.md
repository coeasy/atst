# ADR-007-010：CredentialStore 处置决议（deprecate 而非接线）

- 状态：已接受（Accepted）
- 日期：2026-09-06
- 关联：ARCHITECTURE_AND_OPTIMIZATION_PLAN_v6.md B10 / REFACTOR_PLAN_v7.md §2.8

## 背景

`security/credentials.py` 的 `CredentialStore`（三级凭据回退：keyring → env →
加密文件）自引入以来**没有任何调用方**——仅在 `security/__init__.py` 与主包
惰性导出表中被导出。v7 审计（B10）认定这属于「死能力」：维护成本存在
（测试、文档、API 面），但无实际收益。

## 决策

**标记 deprecated，不强行接线。** 理由：

1. 短期内没有真实需求方：`trade/` 按红线不做实盘（`SocketTransport` 抛
   `TradingUnavailable`），模拟盘不需要凭据；Web cookie 管理当前由
   `web/base.py` 的构造参数直传，无三级回退诉求。
2. 为「可能用得上」而保留完整三级存储属于过度工程（v6 §5 明确不做清单的
   同款逻辑）。
3. 若 v8 中 trade 模拟器或 CLI `--credential-source` 出现真实需求，再按
   需求形态重新设计（可能只需 env → file 两级），比现在强行接线更干净。

## 后果

- v7：类 docstring 标记 `.. deprecated::`，指向本 ADR；行为与导出不变
  （不破坏任何潜在下游）。
- v8：仍无调用方 → 整体删除 `CredentialStore` 及其导出、测试、文档。

## 备选方案（未采纳）

- **接入 trade 模拟器**：模拟盘无凭据需求，为接线而接线。
- **接入 CLI --credential-source**：CLI 当前无需要凭据的子命令，同上。
