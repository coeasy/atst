# atst v1.1.0

发布日期：2026-10-02（tag `v1.1.0`）

状态：**GitHub Release 已发布**（canonical wheel + sdist，附 `SHA256SUMS.txt` 与
`RELEASE-METADATA.json`）；**本包不在 PyPI 上**——PyPI 上传是显式 opt-in
（仓库变量 `PUBLIC_RELEASE=true`），尚未执行。GitHub Release 与 PyPI/Docker 发布是两条独立动作，
本版只走通了前者。

## 这一版收口什么

v1.1.0 是 V6 L3 的正式落地版本：把三条「事实与说法脱钩」的账做成正面——三源真实可用、
执行器分派泛化、以及一处核心链路断链被修回连通。内核架构（单执行路径 / 零缓存 / provider-first /
禁止隐式跨源 fallback）不变，规模数维持 **14 Provider / 176 capability / 262 条精确绑定**。

### Added — V6 L3 三源落地

新增三个 Web Provider 与 7 个数据型能力（返回均为 `dict` 列表，不套 `Quote`/`Bar` 行情模型）：

- **`cninfo`（巨潮资讯网法定披露）**：`announcements`（A 股公告，含 PDF 直链）、`hk_announcements`（港交所公告）。
  巨潮要求 `stock=代码,orgId`，适配器先打一次代码联想拿 `orgId`（进程内记这一项元数据），
  查不到直接报错，绝不发「注定返回 0 条」的请求。
- **`ths`（同花顺）**：`limit_pool`（涨停/跌停/炸板池）、`theme_attribution`（涨停板块聚合含成分股）、
  `concept_members`（板块成分股摊平）、`hot_rank`（人气榜）。
- **`wallstreet`（华尔街见闻）**：`breaking_news`（全球快讯，仅 `global-channel` 稳定返回，
  故只挂这一个能力）。

### Changed — 执行器分派泛化

`runtime/executor.py` 的 `_web_adapter_call` 不再写死 `fetch_bars`，改为按
`MigratedCapabilityBinding.method` **动态分派**（缺省回落 `fetch_bars`）。四张服务面
（CLI `atst query <capability>` / HTTP `POST /v13/query/{cap}` / WS `query` / Python `Client.call`）
统一把 `args`/`kwargs` 透传进内核——web_adapter 源的 `symbol` 走 `args[0]` 或 `symbol=` 关键字，
契约层 `_validate_web_adapter` 对「不接受标的」的能力（如 `breaking_news`）显式拒绝（`E1010`）
而非静默忽略，避免把「没筛」伪装成「筛过了」。

### Fixed

- **`ths.concept_members` 核心链路断链**：此前取板块成分股时先按 `block_code` 过滤、紧接着又按
  股票 `code` 二次过滤，导致传入**板块代码**必然返回 `[]`（断链）。现改为互斥分支：
  板块代码 → 按 `block_code`、股票代码 → 按 `code`、不给 `symbol` → 全市场并按 `limit` 截断
  （上游 `block_top` 忽略 `limit`，本地兜底）。新增回归测试 `tests/web/test_v6_new_sources.py`
  锁定「按板块过滤 / 按股票过滤 / 全市场截断」三种口径。
- **`ths._parse_hot_rank` 孤儿变量**：移除冗余未用的 `code2`，消除孤儿逻辑。

## 兼容性

- Python：`>=3.10`，支持 CPython 3.10、3.11、3.12、3.13、3.14（3.13/3.14 的 argparse `%` 与
  `asyncio.start_server` 同步回调两类解释器陷阱由门禁守住，见 `tests/compatibility/test_interpreter_hazards.py`）。
- 核心安装零硬依赖；DataFrame / Parquet / DuckDB / Web / Metrics / Server / MCP 按 extras 安装。
- 同步 `TdxClient` 与异步 `AsyncTdxClient` API 保持镜像语义。
- 新增能力均为「数据型源」，不参与行情降级链；返回形状见 `docs/api/interfaces.md` 的 V6 L3 调用口径。
- 门禁阈值未动：离线整仓覆盖率阈值与 mypy/ruff 的 strict 项一律不下调。

## 安装

> **实测口径**：`https://pypi.org/pypi/atst/json` 与 `https://pypi.org/simple/atst/` 均回 404——
> PyPI 上没有 `atst` 这个名字，`pip install atst` 今天装不通。可执行的路径是下面两条。

从源码安装（当前稳定线）：

```bash
git clone https://github.com/coeasy/atst.git && cd atst
pip install ".[all]"
```

或安装构建产物（由发布流水线产出）：

```bash
# 本地复刻产物形态：
python scripts/build_package.py            # 产出 dist/atst-1.1.0-py3-none-any.whl 与 sdist
pip install dist/atst-1.1.0-py3-none-any.whl
```

## 发布链走到哪一格

`wheels.yml` 由 **published 且非预发布** 的 GitHub Release（经 `v1.1.0` 标签触发）驱动：
安装矩阵 → PyPI Trusted Publishing（受 `PUBLIC_RELEASE` 开关控制，本版仍为 false）→
把 wheel/sdist 附加到 Release 资产栏 → Docker 复用同一个已验证 wheel。本版走到的是
**GitHub Release 已发布**；PyPI 上架是另一条独立且不可逆的动作，由维护人显式开启。

## 已知边界

- `announcements` 带标的时依赖巨潮 `orgId` 联想；网络不可达时该能力按设计 `WebSourceError` 失败，
  不降级、不回填。
- `breaking_news` 不接受 `symbol` 参数；传之在契约层即被拒。
- `limit_pool` / `hot_rank` / `theme_attribution` / `concept_members` 的 `symbol` 是**本地筛**
  （先取回全量再按代码比对），语义正确但不省流量。
- 真实 Web 数据源可用性取决于服务端状态；联网能力不作为离线门禁。
