# atst v1.1.0

发布日期：2026-09-22（tag `v1.1.0`）

状态：**开发线版本**。`v1.1.0` 是一个**已推送到 origin 的 tag**，不是一次发布——本包当前
**不在 PyPI 上**（见下"安装"），GitHub Release 与 PyPI/Docker 发布是人工动作，尚未执行。
`v1.0.0` 仍是文档口径上的最新稳定版。

## 这一版收口什么

v1.1.0 是 v1.x 单内核线的收口版本，不改架构，只把三条"事实与说法脱钩"的账做成正面：

- **解码越域值现在在结果里看得见（G7）**：新增 `WarningCode.FIELD_OUT_OF_DOMAIN`（告警码共 15 个）。
  记录布局尚未由真机 golden 锁定的命令（`0x000F` 资本变动 / `0x0010` 财务）页内字节数对得上、
  解码层因此一个字都不记，而值已经错位——现在出口处那把尺子（`atst/domain/integrity.py`）会量出来，
  随 `ResultMeta.warnings` 上 CLI/HTTP/WS/MCP/库五张面；`strict=True` 时升级为 `TruncatedDataError`。
  **布局本身没有被修好**，这一格修的是"调用方能否看见"。
- **协议状态表回到命令账本这边（G8）**：`docs/tdx_status.md` 按命令账本与客户端拦截表重写，
  并写明 `Quote` 的 `datetime`/`bid`/`ask` 在 7709 实时路径上恒空及其来源；
  新增门禁 `tests/architecture/test_tdx_status_matrix.py`（7 项）钉住幻影命令号、
  给被拦命令盖 ✅、写错异常类这三类回潮形状。
- **7709 核心链第一次跑进交易时段排期（G4）**：`tests/live/test_tdx_core_chain.py`（5 项，
  `-m network`）+ live-smoke 工作日 02:30 UTC（北京 10:30）调度；主链接不上时它**红而不 skip**。
  断言全部要求 `meta.provider == "tdx"` 且未被兜底，web 兜底救活的绿灯不算数。
- **安装口径按实测改写（G9）**：`pip install atst` 此前在四份文档里写成可用指令，
  而 PyPI 上这个名字不存在。现在四份文档给的是能跑通的两条路径，并有一条门禁拒绝未上架的指令。
- **`market` 旋钮的对外契约变宽（第 13 轮，`1.0.0` 之后）**：`"0"/"1"/"2"` 与 `sz/sh/bj` 在六张面上
  同答案；值域由入口解析器那张表派生，越界写法照旧全拒。

## 兼容性

- Python：`>=3.10`，支持 CPython 3.10、3.11、3.12、3.13。
- 核心安装零硬依赖；DataFrame / Parquet / DuckDB / Web / Metrics / Server / MCP 按 extras 安装。
- 同步 `TdxClient` 与异步 `AsyncTdxClient` API 保持镜像语义。
- **唯一的"以前静默、现在出声"变化**：越域字段行会带 `field_out_of_domain` 告警。
  依赖"结果一定干净"的调用方在 `strict=True` 下会开始收到 `TruncatedDataError`——
  那正是这一格的目的：那批数据本来就不干净。
- 门禁阈值未动：离线整仓覆盖率 `fail_under = 77` 与 mypy/ruff 的 strict 项一律不下调。

## 安装

> **实测口径（G9，2026-09-22）**：`https://pypi.org/pypi/atst/json` 与
> `https://pypi.org/simple/atst/` 都回 **404**——PyPI 上没有 `atst` 这个名字，
> `pip install atst` 今天装不通。可执行的路径是下面两条。

从源码安装（当前开发线）：

```bash
git clone https://github.com/coeasy/atst.git && cd atst
pip install ".[all]"
```

或安装构建产物：

```bash
python scripts/build_package.py            # 产出 dist/atst-1.1.0-py3-none-any.whl 与 sdist
pip install dist/atst-1.1.0-py3-none-any.whl
```

## 发布链走到哪一格

`wheels.yml` 由 **published 且非预发布** 的 GitHub Release 触发：安装矩阵 → PyPI Trusted Publishing →
把 wheel/sdist 附加到 Release 资产栏 → Docker 复用同一个已验证 wheel。本轮走到的是 **tag 就位**；
往下的 Release 点击是公开且不可逆的动作，由维护人执行。执行后本文件"安装"一节才需要按 PyPI 口径改写
（那条 G9 门禁会随文档改动一起复检）。

## 已知边界

- `0x000F` / `0x0010` 的记录布局仍待真机 golden 定标（命令账本 `tier=L2, verified=False`）；
  本版提供的是**看见错值**的机制，不是修好的值。
- `minute`(0x0537) / `trades`(0x0FC5) / `security_list`(0x044D) 在任何 Provider 上按设计 fail-fast，
  入口形状仍在；`fund_estimate` 的口径等裁决。
- 真实主站、Web 数据源与 F10 内容是否可用取决于服务端状态；联网能力不作为离线门禁。
