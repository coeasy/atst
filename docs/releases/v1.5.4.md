## 一句话

v1.5.3 之后的继续审计修掉三处"同一份库、两张面/两个源给不同答案"：`minute_klines`
默认源选错、CLI `--period` 别名与库面分叉、腾讯 mkline 分钟戳形状与其它源不同。

## Fixed

### `minute_klines` 默认源：按市场分叉

`atst.catalog.capability._DEFAULT_PROVIDER["minute_klines"]` 原写 `"derived"`，而该能力没有
derived 绑定——这一格被 `any(item.provider == configured ...)` 静默跳过，默认源落回硬编码
优先级表里排在 `tencent` 前面的 `eastmoney`。实测（2026-10-20）东财 `push2his` /
`92.push2his` / `push2delay` 三台主机同时 `RemoteProtocolError`，`atst minute-klines 600519
--period 5min` 三连失败且 `provider_switch_allowed=False`，而同刻腾讯 mkline HTTP 200。

现在 `default_provider_for(capability, symbol=None)` 对 `minute_klines` 按市场分叉：

| 市场 | 默认 Provider | 原因 |
| --- | --- | --- |
| A 股（sh/sz/bj） | `tencent`（mkline） | 唯一服务 A 股分钟 K 线的免鉴权源 |
| 港股 / 美股 | `eastmoney`（push2his） | 腾讯 mkline 对港美返回 `code=-1` 空数据 |

`Client.call` 从位置参数取第一个符号串（`_symbol_hint`）传给默认源解析，CLI / HTTP / WS /
MCP 四面同路。显式 `provider=` 与"失败不换源"的语义不变。

### CLI `--period` 别名从域词表派生

`atst.cli._common` 手抄了一份别名表 `{"1","5","15","30","60","d","1d","1day"}`，于是
`atst minute-klines 600519 --period m5` 报「未知 K 线周期 'm5'」，而 `Client.bars(period="m5")`
能取到数据。别名表现改为从 `atst.domain.period.PERIOD_ALIASES` 派生（`m5` / `5m` / `daily` /
`1h` 等一律可解），CLI 特有的裸数字写法（`--period 5`）保留。

### 腾讯 mkline 分钟戳形状

mkline 返回紧凑 12 位 `"202609291455"`，而 tdx / 东财是 `"2026-09-29 14:55"`、新浪是
`"2026-09-29 14:55:00"`。现在 `atst.web._paginate.rows_to_bars` 在行 → `Bar` 的唯一入口把
12 位紧凑戳展开成 `"YYYY-MM-DD HH:MM"`；已带秒的行原样通过（不截断秒位）。
