## 一句话

把**复权这件事做完、做对**，并在它上面立一个端到端的数据产品：新增宽表日线
`daily_enriched`（24 列，一行一交易日，复权 K 线 + 东财估值等值连接）与配股事件源
`rights_issue`；同时根治三处**会静默出错**的复权缺陷——后复权因子随 `count` 漂移、
组合能力上 `provider=` 是死参数、`events=[]` 被当成"没给"。

## Added

### 宽表日线 `daily_enriched`（组合能力）

一行一交易日，**24 列** = K 线 6 列 + 派生 6 列 + 估值 9 列 + 3 列来源标注。日 K 线
（`adjust` = `none` / `qfq` / `hfq`）与东财逐日估值（`RPT_VALUEANALYSIS_DET`）按
**交易日等值连接**——不做 as-of 前向填充，因为前向填充就是把昨天的估值当今天用。

拼装是**纯函数**（`atst/domain/enrich.py`），不碰网络，所以四条容易写错、写错也不报错的
口径可以被单测直接钉住，并写死在该模块 docstring 里：

| 字段 | 口径 | 标注 |
|------|------|------|
| `pre_close` | 窗口**前一根** K 线的收盘（不是当日 `open`、也不是循环里的前一根） | 缺失时为 `null`，`pct_chg` / `amplitude` 也是 `null`（不拿 0 硬算） |
| `turnover` | `raw_volume / FREE_SHARES_A × 100`，分子是**复权前**的量（股） | 复权后的 `volume` 与历史流通股本不是同一尺度，故读 `bar.extra["raw_volume"]` |
| `vol_ratio` | `raw_volume_t / mean(raw_volume_{t-5..t-1})` | 恒带 `vol_ratio_basis="daily_approx"`——真实量比是盘中概念，日频只能近似，不冒充 |
| `is_st` | 简称**前缀**是否 `ST` / `*ST` / `SST` / `S*ST` | 恒带 `is_st_source="name_heuristic"`；**拿不到简称时是 `null` 而不是 `false`** |

`count` 卡在**估值序列的单页上限 500**：超限当场 `E1010`，不静默截断（截断会让更早的行
估值列全 `null`，调用方分不清"那时没有估值"和"我没取到"）。更长区间用 `start` 分段。
当日 0 成交时 `turnover` 与 `vol_ratio` 都是 `null`——零成交意味着这两个指标没有定义。

四面全通：Python `Client.daily_enriched(...)` / CLI `atst daily-enriched sh600519 --adjust hfq` /
HTTP `POST /v13/query/daily_enriched` / WS `{"method":"query",…}` / MCP `query_capability`。

### 配股事件源 `rights_issue`

复权除权价公式 `P_ref = (P − D + P_r·R)/(1 + S + R)` 里的 `P_r·R` 项此前**恒为 0**——
东财分红表没有配股列，于是配股标的的因子系统性偏小。现在 `dividend_history`
（`RPT_SHAREBONUS_DET`：送股 / 转增 / 派息）与 `rights_issue`（`RPT_IPO_ALLOTMENT`：
`PLACING_RATIO` / `ISSUE_PRICE`）**两路按除权日合成一天一条**再进引擎。拆开会丢 `S·R` 交叉项。

### CLI

- `adjusted-bars` 补齐 `--start` / `--provider` / `--event-source` / `--anchor-date`。
- 新增 `daily-enriched`（`--count --start --adjust --provider --event-source`）。
- CLI 现为 **33 子命令 / 38 个叶子命令**。

## Fixed

### 后复权 / 定点复权因子随 `count` 漂移（**静默错，不可复现**）

后复权因子是 `∏ 1/k_d`，`d` 遍历**全部**事件日（含窗口之前的），而每个 `k_d` 都要事件日的
**前收盘价**。窗口盖不住最早事件时，引擎只能走 `1/(1+S+R)` 降级口径、现金红利被整项丢掉，
于是**同一根 bar 在不同 `count` 下复权结果不同**：实测某标的 hfq 因子 `1.045` 与 `1.642` 并存。
拿短窗口做回测，早期因子的偏差会被当成真实价格。

修法：`hfq` / `fixed` 把取数窗口**按倍数向后延伸**（×4，硬顶 20000 根），直到盖住最早事件
或触到历史尽头；返回给调用方的仍只有它要的那 `count` 根。`qfq` **不延伸**——它归一到最后一根，
窗口前的常数因子在归一化时约掉。修后四个标的在 `count=5 / 60 / 2000` 下因子**完全一致**：

| 标的 | hfq 因子 |
|------|----------|
| `sh600519` | 7.39106838 |
| `sh601398` | 2.56716562 |
| `sz000001` | 155.67349278 |
| `sh600601` | 116.77316777 |

延伸取数失败不再静默退回原窗口（那意味着"这次的早期因子可能是漂移值"），改记
`adjust_window_extend_failed`。同一根 bar 在不同批次值不一致会让下游对不上账，所以
`daily_enriched` 的 `hfq` 走同一条延伸逻辑。

**独立校验**（不看引擎自身算术）：`sh600519` 的 hfq 与 raw 在**非除权日逐根收益率完全一致**
（0 处不符）；事件日反推的每股分红与公告精确对上（2024-06-19 = 308.76 元/10 股、
2024-12-20 = 238.82、2011 年 `10送1派23` 得 `1/k = 1.112029`，含送股与派息的交叉项）。

### 组合能力上的 `provider=` 是死参数

`Client.adjusted_bars(..., provider="tdx")` 在规划期就被判成
`E1010 provider 'tdx' 不支持 capability 'adjusted_bars'`，而执行体里读 `kwargs["provider"]`
的那一行**永远读不到东西**。组合能力（`adjusted_bars` / `daily_enriched` / `sync_daily`）没有
自己的传输层——它名字里的 `provider` 指的是"取**未复权原始 K 线**的那条腿"，不是"谁来执行"。
现在 `Client.call` 对 `catalog/capability.py` 的 `COMPOSED_CAPABILITIES` 把这个值归位到
`options.kwargs`，执行体才拿得到。与之相对，`web_adapter` 一类的 `provider` 仍是路由字段。

### 其余修复

- **前收盘价按"循环里的前一根"定位**：同一间隔内多个事件共用同一个基准价。改为按**事件日**
  `bisect_left` 定位。
- **复权后的 `volume` 被拿去算换手率 / 量比**（尺度错配）。`AdjustEngine.apply` 现在把复权前的量
  留在 `bar.extra["raw_volume"]`，并给出 `adj_price_factor` / `adj_volume_factor`。
- **`event_source="tdx"` 炸成 E9000**：`_adjusted_events` 对已经是 `CapitalChange` 模型的返回值
  又套了一层 `to_capital_changes()`（它吃的是解析行 dict），每次都在 `row.get(...)` 上抛
  `AttributeError`，被兜成一句只对内部说得通的 `E9000`。改为按类型分派，错误回到它该在的地方
  ——布局闸给出的 `E1010`，并提示改用 `event_source='eastmoney'`。
- **`events=[]` 被当成"没给"**：显式清空事件集会被静默换成"去东财拉一份回来"，同一句话两种结果。
  三态分清：`None`（没给）才去取，`[]` 就是**不调整**，非空则跳过在线取数。
- **`is_st` 在拿不到简称时返回 `False`**（"不知道"冒充"不是 ST"）：改为 `None`。
- **无成交日的 `vol_ratio` 报 `0.0`**：与 `turnover` 同口径改为 `null`。
- **`EastmoneyMarginSource.parse_rows` 忽略 `allow_empty`**：稀疏报表（东财 `9201`
  「返回数据为空」）会被当成错误。
- 复权事件取数显式分页到尽：`dividend_history` 的 `size` 默认只有 20，长历史标的的早期事件
  会被静默截断（600519 实有 28 条）。触顶记 `WEB_EASTMONEY_PAGE_LIMIT`。

## 已知边界

- **复权因子不落盘**：每次调用都在内存里重算。这是本轮唯一未关闭的复权缺口。
- `0x000F`（TDX 除权除息）的记录布局**仍未**由真机 golden 锁定，`event_source="tdx"` 会被
  布局闸拒绝——这是刻意设计，错位的复权比不复权危险。
- `vol_ratio` 是**日频近似**，不是盘中量比；`is_st` 是**名称启发式**，不是交易所风险警示名单。
- 上游 TDX `bars` 在盘中未开盘时会回一根 `volume=0` 的**当日占位 bar**（`close` 沿用昨收），
  宽表会如实带出来——早盘跑宽表看到末行 `null` 是上游形状，不是缺数。
