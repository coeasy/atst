# v1.4.2 — 同步脚本记账与校验修复

发布日期：2026-10-04 · 类型：patch · 目标：Python 3.10+

紧接 v1.4.1（全历史修复 + 升序契约）之后，对 `scripts/sync_daily_history.py` 的
当轮重投链路做了一轮全面复审（主体流程连通性 / 断链 / 孤儿逻辑 / 死循环逐项核查），
修掉 2 个真实记账缺陷、清掉 1 处孤儿分支、补上 1 处入口校验。

## Fixed

- **重投成功后 `state.failed` 残留假失败**（v1.4.1 引入）：首轮 SKIP 会把标的写进
  `state.json` 的 `failed`，当轮二次重投成功后却不清除——该标的永远顶着"它失败过"
  的记录，`--doctor` 的 failed 读数被污染。现在重投 OK 时同步 `pop` 掉旧记录。
- **重投后进度越界**：重投循环继续累加 `completed`，最终进度行会打出
  `进度 30/28` 这类越界读数。重投只**替换**终态，不再累计 completed。

## Changed

- **`--lookback` 前置边界校验**：合法区间 `1..65535`（客户端对 `count` 的硬上限是
  协议分页地址空间 `0xFFFF`）。越界值原先会变成"逐只 ValidationError → 全员 SKIP"
  的静默风暴，现在入口直接拒绝并说明区间。
- **`_validate` 移除两个不可达分支**（孤儿逻辑）：它只吃 `_dedup_merge` 的输出
  （键齐、升序），"取不出日期键"与"日期非升序"两分支在真实调用链上永不触发。
  排序责任收敛在 `_dedup_merge` 一处；`_validate` 只查 OHLC 自洽与 volume 单位。

## Docs

- cookbook `--lookback` 参数行补合法区间；「常见坑」新增一行解释"个别 SKIP 在
  结尾汇总里消失"是当轮重投的正常表现（含 `state.failed` 假失败清理语义）。

  `state.failed` 假失败、重投仍 SKIP 时终态记账恰好一次（completed 不越界）。
- `--lookback` 越界拒绝用例（0 / 负数 / 70000 全部入口拦截）。
