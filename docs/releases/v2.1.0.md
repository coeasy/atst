# v2.1.0 发布说明

> tag：`v2.1.0` · 版本单一事实源：[`atst/_version.py`](../../atst/_version.py) = `2.1.0` ·
> 上一版本：[v2.0.0](v2.0.0.md) · 本次发布：[`v2.1.0`](https://github.com/coeasy/atst/releases/tag/v2.1.0) · 目标：Python 3.10+
>
> **发布后从 PyPI 安装**：`pip install atst==2.1.0`。定为 MINOR：只加能力与修复，
> 对外查询契约（路由 / 字段保留规则 / K 线时间语义 / symbol 归一化）不变；排名文件升到 V2
> 但**可读 V1**，升级不丢已有排名。

## 一句话

v2.1.0 把主站候选池从"编译进 wheel 的固定名单"变成**可运维的活池**：`atst hosts discover`
从本机通达信与开源清单发现新主站并实测采纳，排名文件带上观测时间，`hosts scan` 扫全池并在
同一轮淘汰不可达项，`hosts list` 给出观测年龄与过期提示——全程不需要升级版本。

## 为什么重要（实测依据）

内置池编译进 wheel，只随版本变化；旧池 2026-11 复测时标准族 14/29 可达、最好 22.8ms。
本机通达信 `connect.cfg` 里 33 台 7709 端点**全部可达**、最好 8.9ms，其中 31 台不在内置池。
这些主站过去只能用 `ATST_HOSTS` 或手改排名文件才能用上，而排名文件没有任何时间字段：
一台掉线的主机会带着三天前的 12ms 证据永远排在最前。

v2.1.0 之后，一次 `atst hosts discover` + 一次 `atst hosts scan` 就能把候选池换成当天实测的
名单；实跑结果：候选 94 台 → 可达 57 台 → 采纳 57 台（49 台不在内置池），`hosts list` 首位
从 22.8ms 变成 12.4ms，冷启动 `quotes("sh600519")` 199ms（含构造）。

## Added

- **`atst hosts discover`**：来源 `tdx-install`（默认，读本机 `connect.cfg`）/ `gotdx` /
  `mootdx` / `pytdx` / `file`（`.cfg` / JSON / Python 元组表 / Go 结构体表，按内容形状猜格式）。
  `--source` 可多次指定并合并去重，`--dry-run` / `--no-verify` / `--report` / `--json` 分层可控。
  候选按端口归族（7709/7719 → 行情，7727/7615 → 扩展，80/443 丢弃），实测判定是
  "握手 + 心跳回包"，TCP 可连但协议不应答的主机不算通过。
- **`RankingStore.freshness()` / `RankingFreshness`**：条目数、文件更新时间、最老/最新观测与年龄；
  文件缺失或损坏返回空读数而不抛。
- **`atst hosts scan --workers / --samples`**：候选池 70+ 台，并发度与采样次数不再写死。
- **Client 便捷方法**：`adjusted_bars` / `capital_changes` / `finance` / `f10` / `ex_bars` /
  `goods_bars` / `mac_quotes` / `local_finance`。
- **`atst.output.query_parquet`**：对落盘 parquet 目录做只读 SQL（DuckDB 视图），只放行单条
  SELECT/WITH，按 DuckDB 自身解析器裁决而非关键字子串扫描（字面量与注释拆词都绕不过）。
- **MCP `capabilities` 工具**：与 CLI 同源的发现面。

## Changed

- **排名文件 V2**：新增 `observed_at`（epoch 秒）。成功观测打时间戳、失败观测仍删条目；
  V1 可读（读作 `None`，不伪造 now），下一次写入自动升级。
- **`hosts scan` 扫全池**：内置池 ∪ 排名 extras（`ATST_HOSTS` 存在时只扫覆盖名单），
  失败项同轮淘汰——一条命令同时完成"刷新 + 淘汰"。
- **`hosts list` 保鲜视图**：观测年龄、来源（`discovered`）、extras 计数，最老观测超 7 天提示重扫。
- **`hosts list` 移除 `--timeout`**：它只读排名文件、不建连，留着被忽略的 flag 会让人误以为在探活。
- **流式面补齐元信息**：`on_quote` payload 在确有其事时携带 `observed_at_ns` 与 `warnings`；
  无 provenance / 无告警时形状与历史逐字节一致，不制造 `warnings: []` 这种"看起来查过"的假信号。
- **服务面标量宽容**：HTTP / WS / MCP 的数值参数接受 `"3"` 这类字符串并按声明类型转换。

## Fixed

- **合并点丢失 `observed_at`**：既在内置池又在排名文件里的主机显示"有 rtt 但观测年龄 `-`"。
  落盘、读数、展示三处各自都对，只有 `_apply_ranked_observation` 悄悄把 V2 语义抹掉。
- **`hosts scan` 被 `max_hosts=64` 截断**：被截掉的恰好是从没测过、`score=1e6` 排最后的那批。
- **`connect.cfg` 解析**：`\s*` 跨行把 `Port05=7709` 读成地址；CRLF 下 `$` 不吃 `\r` 导致整份文件
  解析出 0 条。改为 `[ \t]` + `\r?$`，`Port=0` / 空地址 / 重复条目逐条跳过。
- **7727 扩展主机被当行情探测**：18 条伪 ERR 行，改为按端口归族后过滤。
- **Client 蹦床递归无上界**：越界抛 `InternalError`，不再撞 Python 递归上限。
- **传输层 cleanup 等待无界**：关闭按上界等待，避免关停卡在僵死连接上。

## 升级

无需改代码。`pip install -U atst` 即可；已有 `~/.atst/server_ranking.json` 会在下次
`hosts scan` / `discover` 时自动升到 V2。

想立刻把候选池换成当天实测名单：

```bash
atst hosts discover --source tdx-install --source gotdx   # 发现 + 实测 + 采纳
atst hosts scan                                            # 全池复测，顺带淘汰不可达
atst hosts list                                            # 看观测年龄与来源
```

回滚：`rm ~/.atst/server_ranking.json`（候选退回内置池顺序，首次请求照样成功）。
定时保鲜建议用 crontab / 计划任务每天开盘前跑一次 `atst hosts scan`。
