## 一句话

把"选源"从**隐式行为**变成**可声明的请求参数**（`provider="auto"`），并顺手把三条
"帧合法、值可疑"的静默缺陷堵死：百度行情走错能力（K 线冒充五档）、解析器内部标记
泄漏进公开 dict、`hosts scan` 只看前八台导致主站自我锁死。四组永久回归判据跟上，
`quotes` / `bars` 的行出口统一成文档里写的那种 dict。

## Added

### `provider="auto"`：显式自动选源

此前"自动选源"只存在于**主站层**（同一 Provider 内挑最快 IP），Provider 层是钉死的：
一次请求 = 一个 Provider，跨源只能靠调用方显式给 `FallbackPolicy`。想"能取到就行、
别管哪家"的调用方没有一句话可说——只能自己写循环。

现在有了一个显式的名字：

```python
from atst import Client

result = Client().quotes("sh600519", provider="auto")
result.provenance.provider              # 实际出数的 Provider
result.provenance.requested_provider    # "auto"
result.provenance.fallback              # 是否换过源
```

候选顺序**每次请求现算**，三段：

| 段 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 能力面 operational 的 Provider | 该 capability 在该 Provider 上真的可用（登记序） |
| 2 | `[routing] auto_providers` | 调用方给的偏好，按给出顺序前插 |
| 3 | 运行时健康反馈 | 最近失败过的沉底，TTL 过后自动复位 |

健康反馈来自 `ProviderHealthStore`：**只记真实请求的成败**（失败打标、成功清除），
不主动探测——它不是一个后台探针，是"这台机器刚刚被谁坑过"的短期记忆。TTL 默认
90 秒（`[routing] auto_health_ttl`），过期即复位；复位时按**对象身份**比对，避免把
这期间新写入的那条失败标记一起清掉。

跨源出数**不静默**：`provenance.requested_provider="auto"`、`fallback=True`，并附一条
`auto_provider_fallback` 瑕疵（`docs/errors.md` 有它的取值与读法）。候选全灭抛
`AllSourcesExhausted`，不返回空结果。钉死 Provider 的请求**永远不经过这条路径**——
`provider="tdx"` 就是 `tdx`，不会因为 `tdx` 失败而换成别家。

`quotes()` 与 `quotes_batch()` 同语义：批量不是"把 `auto` 解析成第一跳后按单跳执行"，
而是每只标的各走完整候选链。否则同一个 `auto` 在单只与批量两条路上会给出两种行为——
批量那只失败时直接进 `errors`，永远不会换源。

### `runtime.health` 新增 `provider_health`

健康反馈是个**隐式**机制：`auto` 会因为你上一条请求失败而把某家沉底 90 秒。没有这个
字段，运维看到 `auto` 挑了次优 Provider 时无从知道"为什么"——隐式机制必须可观测。

```json
{"provider_health": {"tdx": {"code": "E2040", "age_s": 12.5}}}
```

只列**仍处 TTL 窗口内**的标记，读取时即复位过期项——报的名单与 `auto` 排序时用的是
同一份，不会出现"健康面说降级、排序却当它没事"的分叉。`age_s` 是距今秒数而不是时间戳：
`monotonic_ns` 只在同一进程内有意义，贴到线上接口没有价值。`auto_health_ttl=0`（关闭
健康反馈）时恒为空 `{}`。HTTP `/v13/runtime/health` 与 WS `runtime.health` 同值。

### `quotes(strict=True)`：把"值可疑"变成失败

解析器一直在做自校验（回声哨兵失配、成交额越界等），但结果只写进
`extra["_warnings"]`——帧合法就照常返回，调用方不主动查就永远不知道。`strict=True`
把这个名单接成开关：任何一条瑕疵都判 `IntegrityViolation`。

四面同名可用，同一个判据：

| 面 | 写法 |
| --- | --- |
| Python | `Client().quotes(sym, strict=True)` |
| CLI | `atst quotes sh600519 --strict` |
| HTTP | `POST /v13/quotes?strict=true` |
| WS | `{"method": "quotes", "params": {"strict": true}}` |
| MCP | `get_quote` / `get_quotes` 的 `strict` |

`bars` 早就有这个参数，本轮把它在 MCP 面补齐（此前只有 Python/CLI 两面有）。

### canonical dict 行契约

`quotes` / `bars` 的行出口统一是 **dict**（`result.data[0]["price"]`），与 quickstart 与
cookbook 里写的一致。Web 源此前返回 `Quote` / `Bar` 数据类，按文档取键的代码会撞
`TypeError`——文档与实现对不上，且只在换源时才暴露。域模型仍是 `Client.typed()` 的契约，
没有退化。

### `Quote.datetime` 回填

`atst/web/normalize.py` 里的 `quote_datetime_from_extra()`：tencent 14 位紧凑串 /
sina `date+time` / eastmoney `f86` / baidu unix 秒统一渲染成市场时区字符串。**拼不出完整
日期时间就留空**，不拿时刻碎片或本机时钟冒充行情时间——一个错误的 `datetime` 比一个空
`datetime` 危险得多。

### `BaseWebSource.fetch_quotes()`

行情快照的唯一语义出口（显式下发 `kind="quote"`）。存在的理由是下面那条 Fixed：
"默认出口"这个概念本身就是错能力缺陷的温床。

## Fixed

### `quotes(provider="baidu")` 静默错能力

内核 quotes 一跳走的是 `fetch()` 的默认出口，而百度财经的默认分组是 **K 线**。
于是 URL 请求 K 线、响应按行情解析——**合法返回 250 根日线冒充五档快照**，字段名对得上，
值全是日线。这是"最坏的一类缺陷"：不报错、不告警、结构合法、量级离谱。

现在 `_web_quotes` 走 `fetch_quotes()`，URL 构造与解析两侧同口径按 `kind` 路由：

```python
if not group:
    group = "quotation_minute_ab" if kind in ("quote", "minute", "ticks") else "quotation_kline_ab"
```

显式 `group` 仍然赢（调用方明确指定时不猜）。

### `atst hosts scan` 只扫当前前八台

排名是**证据**。只扫 top-8 意味着掉出前八的主站永远拿不到新证据、再也回不来——
一个自我锁死的排名。现在扫**整个候选池**（内置池 + `ATST_HOSTS`），`max_hosts=64`；
`TdxClient.bestip()` 保持"刷新当前池"的语义不变（它问的是"我现在该用哪台"，不是
"全市场有哪几台能活"）。

实测（2026-10-19，收盘后）：20 台候选里 7 台可达，RTT 23–61ms；排名文件写入后
`hosts list` 按实时 RTT 给出 8 台；10 只标的全部在得分最高的主站上成功；把死主站
排在池首时一次重试即换台；全死池 1.0 秒内失败并触发后台测速刷新排名文件；无排名
文件的冷启动仍能出数；改写排名文件后下一次 `Client()` 立刻换到新的最佳 IP。

### 解析器内部标记泄漏进公开 dict

`_warnings` / `_tail_leb128` / `_raw_tail_hex` 这些内部标记出现在 `to_dict()` 的出口里，
DataFrame / CSV 的列名被污染。现在解析器的键一律带 `_` 前缀，`Quote.to_dict()` 只扁平化
**非下划线**键。

### `adjusted_bars` 拒绝 `adjustment`

只认 `method`，而 `bars` 的形参叫 `adjustment`——同一件事两个名字，调用方按 `bars`
的习惯写就报 `TypeError`。现在两者等价；同时给出即 `ValidationError`（不猜哪个赢）。

## Changed

- 配置面新增 `[routing]` 段（`auto_providers` / `auto_health_ttl`），段数 **5 → 6**。
  `auto_providers` 拒绝 `"auto"` 自身（嵌套自动选源没有语义）与未知 provider 名
  （拼错静默退回登记序，等于调用方的偏好从未生效）。
- `atst hosts list` / `hosts scan` 的 help 与结论行写明**只覆盖 quotation（STANDARD）族**
  （排名文件也只记这一族），其余四族指向 `hosts audit` 的 `--family`。原来那句"共 N 台主站"
  会被读成"全部主站都在这儿"——而 `hosts audit` 早就在巡检 5 族，CLI 却没有一处说出来。
- `docs/configuration.md` 新增 `[hosts]` 段的"主站择优怎么选"六步说明：分数公式
  （`base × 4^min(failures,8)`，`base` 取实测 RTT）、排名文件的写入条件（只持久化探针
  结果、只对 STANDARD family、永不扩写显式选择器）。
- `docs/api/interfaces.md` 补 `provider="auto"` 一节、`strict` 的四面签名、CLI `--strict`。

## 兼容性

无破坏性变更。`provider` 不传或传具体名字时行为与 1.5.1 完全一致——`auto` 是新名字，
不是新默认。行出口从数据类变成 dict 是**修文档与实现的不一致**（文档一直写的是 dict）；
依赖 `Quote` / `Bar` 数据类的代码请走 `Client.typed()`，那是它的契约。
