## 一句话

把**指数 K 线从"看起来能跑、实际不可用"修成生产可用**，并顺手把同类缺陷连根扫掉：
`0x052D` 的指数位开关原来只在门面和执行器两层生效，连接层把缺省写死成 `False`，
于是 `TdxClient.bars("sh000001")` 直连调用整条记录流错位（日期变成 `10112-28-10`、
成交量变成 1e40）；同时错位日期的告警"有时响有时不响"，以及东财报表按 6 位代码过滤
让指数与深市股票撞码。

## Fixed

### 指数日线不可用：指数位开关漏了连接层

`0x052D` 是指数与股票共用的命令，但**指数每条记录尾部多 4 字节**（上涨家数 + 下跌家数）。
这个差异由 `index=` 这个位开关：

- **位开**：解析器消费那 4 字节，输出 `up_count` / `down_count`；
- **位关**：4 字节不被消费，于是**下一条**记录的 `datetime` 从尾巴上开始读——
  整条记录流从此错位。

因为 LEB128 是变长编码，错位是**混沌**的：偶尔会自己对齐回来，所以"3 根里 1 根是对的"
比整页全错更难发现，而且**第 1 条记录的日期往往还对得上**——任何抽查式的验证都会通过。

推断原本只发生在门面 `Client.bars` 与执行器两层，`TdxClient.bars` /
`AsyncTdxClient.bars` 把缺省写死成 `False`：

| 调用路径 | v1.5.0 行为 | v1.5.1 行为 |
| --- | --- | --- |
| `Client().bars("sh000001")` | 正常（门面已推断） | 正常 |
| `TdxClient().bars("sh000001")` | **错位**（连接层写死 `False`） | 正常 |
| `AsyncTdxClient().bars("sh000001")` | **错位** | 正常 |
| `Client().adjusted_bars / daily_enriched("sh000001")` | 正常（执行器已推断） | 正常 |

现在三层都缺省按代码段自动推断，判据是同一份 `atst.universe.classify_with_index` 段表
（与 `atst universe` 命令同一事实源）；`index=` 显式传入仍可覆盖（用于"段表把某只代码
判错了"的情形）。`EXECUTED_OPTIONS` 仍含 `"index"`，显式覆盖走的是 `options["index"]`，
不是新增的能力参数。

### 错位日期告警"有时响有时不响"

原值域尺子把年份锚定在 4 位（1900–2099）。同批错位数据里：

- `sh000300` 错位后日期形如 `103951-51-43` → 年份 6 位 → 告警响；
- `sh000001` 错位后日期形如 `10479-27-54` → 年份 5 位但月份越界……旧判据没拦住 → **不响**。

即同一批测试数据里，哪只标的能被告警抓住取决于错位后年份碰巧有几位。这是
`field_out_of_domain` 告警不可靠的根因，也是这次缺陷能潜伏很久的原因之一。

现在日期判据按**真实日历**校验（`atst.domain.integrity.date_problem`）：

| 输入 | 判据 |
| --- | --- |
| `2026-10-13` | 合法 |
| `2026-02-29` | **报**（2026 非闰年） |
| `2024-02-29` | 合法（闰年） |
| `10112-28-10` / `5243-00-00` / `8414-91-57` / `10479-27-54` | **一律报** |
| `2026-10-13 `（尾随空格） | **报**（产出方有问题，不算非日期） |

`row_violations` 的告警路径也带出行内位置：`row[1].date:` / `row.bars[1].date:`，
不用逐行找。

### 东财报表按 6 位代码过滤与指数撞码

东财 datacenter 报表按 **6 位代码**过滤、不带市场前缀，所以 `sh000001`（上证指数）与
`sz000001`（平安银行）是同一串码、只差市场位。取指数时这些能力会静默返回平安银行的数据。

`atst/web/corporate.py::report_code_for()` 守卫：指数符号返回 `None`，对应能力返回**空集**
而不是撞码那只股票的数据。指数没有分红、配股、估值、股东户数、两融——空集是正确语义。

### 指数成交量单位

2026-10-13 实测（三家 cross-check），指数与股票的成交量单位规则不同：

| 周期族 | 指数原始成交量 | 股票原始成交量 |
| --- | --- | --- |
| 日线及以上（`day`/`week`/`month`/`season`/`year`） | 按「手」（比同类别股票规则**再小 100 倍**） | `day` 按「股」、其余按「手」 |
| 分钟线（`1min`…`120min`） | **名义值**（恒等于成交额/100） | 按「股」 |

解析器已把日线族的指数成交量折算到「股」，与股票日线口径一致——修后 `sh000001` 的
`amount / volume` 落在 15~17 元（沪市成交量加权均价的合理量级），修前是 1549 元。

分钟线那一格换不出真实成交股数（乘 100 只会得到成交额本身），于是**原样返回**并发
`index_minute_volume_nominal` 告警，提示该值不可与股票分钟线直接相比。指数要量请用日线，
或换 Web 源（新浪/腾讯的指数成交量是「股」，但腾讯的指数 `amount` 恒为 0）。

### 形参标注与实现对齐

`TdxClient.bars` / `AsyncTdxClient.bars` 的 `index` 从 `bool = False` 改为
`bool | None = None`，与"缺省自动推断"的实现语义一致。`None` 同时是类型上可判别的
"未指定"，与"调用方明确要 `False`"区分开。

## Added

### `atst.domain.integrity.date_problem`

字符串日期值域判据：真日历日校验（含闰年）+ 尾随 padding 检测。是"日期写成日期形状但
根本不是日期"这类缺陷的唯一入口，`row_violations` 在解码出口处调用它发射
`field_out_of_domain`。

### 四组永久回归测试，共 188 例

| 文件 | 覆盖 |
| --- | --- |
| `tests/protocol/test_index_bars_layout.py` | 自建指数载荷：指数位对齐/错位对比、全部日线族的成交量因子、分钟线名义值告警、端到端 `TdxClient.bars`（同步 + 异步）、股票负控 |
| `tests/runtime/test_index_bit_inference.py` | 段表同源判据、显式覆盖、非 bool 覆盖 fail-closed、门面缺省不写死、执行器到达底层（含 ETF/LOF/转债/B 股/北交所负控） |
| `tests/domain/test_integrity.py` | 日期值域判据：8 组错位日期一律报、闰年、尾随空格、嵌套结构路径 |
| `tests/web/test_report_code_guard.py` | 撞码守卫：用"任何真实取数都会炸"的子类守网，指数短路 + 撞码对分离 |

**为什么必须自建载荷**：golden 库 `tests/golden/quotation/` 共 530 份样本，`0x052D`
覆盖 14 组 market/code/category 组合，**全是股票**（market 0：`000001` / `300750`；
market 1：`600000`）——**零个指数样本**。指数 `sh000001` 与深市股票 `000001` 是同一串
6 位码、只差市场位，库恰好只有后者。这正是指数尾部 4 字节一直没有 golden 兜底、
缺陷能潜伏许久的原因。测试用 `encode_leb128` + 手工合成的 4 字节 `tdx_float` 自建载荷，
期望值由 `decode_tdx_float` 反算并在导入时断言一次（`0x4D000000 → 134217728`、
`0x4F000000 → 2147483648`）——不写第二份编码器，编码规则若与解码规则不对称，
测试会跟着一起错。

### 标的 × 周期全矩阵测试（230 例）

`tests/protocol/test_symbol_period_matrix.py`，把「不同维度的数据 × 不同标的」这一问
系统化成矩阵，而不是抽查几只。

**分母直接从段表取**：`ASSET_CLASSES` 声明的 54 个代码段（stock 13 / bse 1 / etf 17 /
lof 7 / bond 8 / index 2 / bshare 2）由 `_segments()` 遍历得出——段表一改，分母自动跟
着变，测试不会静默缩小覆盖面。

| 节 | 内容 |
| --- | --- |
| A. 段表 SSOT | 段总数自洽、每段 `classify` 与声明者一致、类别间不重叠、只有 index 类带指数位、每张表指向不同目录、两张名单互斥且覆盖全表 |
| B. 端到端矩阵 | 53 段 × 3 个周期类别（`day`/`week`/`5min`）= 159 格，每格断言 market/code/category 编码、`date_problem` 为空、成交量单位、告警集合 |
| C. fail-closed | 沪深市场位、4 个北交所代码在**发帧前**被拒、显式 `market=2` 不是绕过手段、规划期放行但执行期拒绝、段外代码的兜底行为 |
| D. 周期别名面 | 别名→目标一致、空串拒绝、未知拼写拒绝而非静默改写、strip/lower 归一化、越界编号拒绝、无拼写别名的编号 `9` 仍可寻址、`tick` 无 K 线编号 |
| E. 0x0530 标的维度 | 市场字节反转方向、回声代码/市场不匹配、空载荷占位响应、单批隔离边界 |

**为什么必须有「两张名单」**：北交所段的请求会在发帧**之前**被拦下（`market=2` 未在
symbol-based 7709 请求上验证），所以它进不了「解码得干净」这张矩阵。`test_bars_matrix_and_fail_closed_matrix_partition_the_segment_table`
断言「53 段能解码」与「1 段必须拒绝」互斥且并集等于全表——段表新增一段时，这里会指名
哪一段没有归属。只保留一张名单，缺口就会漏成「没人测过」。

### 成交量乘数的复合口径

指数标的的成交量乘数不是「要么是 100、要么是 1」，而是两条规则**相乘**：

| 组合 | 乘数 | 说明 |
| --- | --- | --- |
| 股票 + `day`/`week`/`month`… | 1 | 按「股」 |
| 股票 + 5/30/60min | ×100 | 按「手」 |
| 指数 + 分钟族 | 1 | 名义值（另发 `index_minute_volume_nominal`） |
| 指数 + 日线及以上 | ×100 | 指数规则，比同类别股票再小 100 倍 |
| **指数 + 5/30/60min** | **×10000** | 「手」族规则 ×100，再乘指数规则 ×100 |

前四格此前已知；**指数 + 5/30/60min 的 ×10000 是本轮矩阵跑出来才发现的**——它落在
「日线及以上」与「分钟线」两个已知格子的夹缝里，没有任何一条既有测试覆盖。

### 0x0530 请求体与回声的市场字节

真机抓包（`PROTOCOL_SPEC/_sniffer/std7709/0530/`，600519，2026-10-13）确认：

- **请求体** = `[0x01, request_market] + code(6s)`，其中 `request_market = 1 - 标准编号`
  （深=1 / 沪=0，由 `quote_request_market()` 承担）；
- **响应回声** = 标准编号（sh600519 实测回声 `0x01`）。

反转只发生在请求方向，响应方向回到标准语义。

## Known limitations

本轮矩阵跑出的三个真实缺口，**已用测试钉住现状、未改生产代码**——三者的修复都需要
真机 golden 定标，不按猜测改解析器。

1. **北交所门面不切源**：`bars` 对 `bj920001` 规划期放行、执行期抛 `ParseError`
   E3040「当前只允许 SZ/SH」；`quotes` 则隔离该标的、错误进 `_collect`。同一条标的
   两条能力失败形态不同，且 `Client.bars()` **不自动切换数据源**。
2. **段外代码兜底成 stock**：不在段表内的代码（`sh604000`、`sz100000`、`sh500000`、
   `sh999999`）被 `classify()` 归为 stock 并照常发请求，服务端回空或占位数据。
   属静默放行，目前无守卫。
3. **`quotes()` 解析期错误不隔离**：`_t_quotes` 里 `split_symbol` /
   `build_realtime_quote_body` 与 `_op_req` 都在 `try` 内，`dispatch` 在 `try` **之外**，
   所以构造失败只淘汰单只、解析失败（回声不匹配 / 空载荷）直接抛出并中断整批。并发版
   `quotes_concurrent` 外层多包了一层 `except Exception`，同一批混坏标的在那边能隔离。
   两侧语义不同，由
   `test_single_batch_quotes_isolates_request_building_but_not_parsing` 钉住。

顺带记录一个**不是缺陷**的现象：可转债 `quotes` 会收到回声 `600839` 的合法帧（5 个
可转债标的全部返回同一个 `600839`），解析器以 `IntegrityViolation` 拦下。这是
`_std7709_quote.py` 早已记录的「错答案 + 合法帧」风险，既有防护在工作——测试的价值是
钉住**不信任服务端回声**这个原则。
