# v1.4.1 发布说明

## 一句话

**让 `bars()` 真正拿到"全量历史"，并把它的返回契约说清楚。** 修掉一个会造成
**静默丢数据**的缺陷——同步脚本 `--full` 的 `MAX_WINDOW=8000` 会把 1996 年前上市的
老股截断约 1.9 年（实测 `sh600601` 真实 8602 根，被砍到 8000）；同时给 `bars()`
补上**升序**返回契约（此前是「页内升序、页间倒退」的锯齿序，`bars[0]` 既不是最早、
`bars[-1]` 也不是最新）。附带把同步脚本的观测输出、限速与北交所边界做了一整轮透明化。

## Fixed

- **`--full` 不再是"打了折的全历史"（静默丢数据，最高优先）。** 同步脚本
  `MAX_WINDOW` 由 `8000` 提到 `10000`。日线全历史的天花板来自"最早上市日"，
  与请求根数无关，2026-09-30 线路实测：
  - `sh600601` **8602 根**（1990-12-19，上交所首个交易日，已证最老）；
  - `sz000001` **8464 根**（1991-04-03）；旧值 8000 会**静默砍掉 464 根**
    （1991-04-03 → 1993-02-14，约 1.9 年）且无任何告警。
  - 新值 10000 留 5.7 年余量（可用到 2032 前后），且远低于 `_t_bars` 的
    `start + count > 0x10000` 分页地址夹；**超量请求不花钱**：换页遇短页即停，
    年轻标的（几千根）请求数与旧值完全一致，只有真正超 8000 根的老股本多打那几页。
- **`bars()` 返回契约改为按 `datetime` 升序。** 分页拼出来的原始序列是**锯齿**的：
  页内升序、页间倒退（每页都比上一页旧），于是 `bars[0]` 并非最早、`bars[-1]` 并非
  最新——线路实测 `sz000001`/16000 根：`bars[0]`=2023-06-15 而 `bars[-1]`=1993-02-16，
  **两端都不是极值**。现在在出口统一排序，四张面一致：`rows[0]` = 最早、`rows[-1]`
  = 最新。这是此前**既无判据也无文档**的契约空洞，调用方只能各自防御性排序。

## Changed

- **同步脚本观测输出深度优化**（提交 `90712ce`，本次随版发布）：
  - **进度行节流**：默认只在终端用回车覆盖刷一行，非终端按阈值平铺，不再每只
    `print+flush`（全市场 8733 只 = 8733 行刷屏 + 约 87 秒纯空转）；明细只在
    `--verbose` 时逐只打印，问题清单在结尾统一汇总；
  - **礼貌间隔移到提交侧**：`--gap-sleep` 只在 ≥0.05s 时夹在 `submit` 之间才有意义
    （真实限速仍在连接池 `slots_per_host` / `SessionRateLimiter` 那层）；
  - **vipdoc 跨平台探测**：不再硬编码 `C:/new_tdx`、`D:/new_tdx`（POSIX 下会被
    当成相对路径），Windows 回两盘符、其他系统回 `~/new_tdx`、`/opt/new_tdx`、
    `~/.wine/drive_c/new_tdx`；
  - **`run()` 收尾 `finally` 关连接池**，不留孤儿连接 / 心跳线程；
  - **`scan_universe` 的 `warnings` 抑制改为局部**（`catch_warnings`），不再全局泄漏；
  - **砍掉 `sync_one` 里与连接池重复的"只对 timeout 重试一次"孤儿逻辑**（连接池
    `max_retries=3` 已覆盖），只留"取不到就 SKIP"，断链清晰；
  - **当轮 SKIP 二次重投**：首轮 SKIP（主站瞬时抖动）在收尾前自动再投一次，压低
    单次运行 SKIP 率；REJECT / EMPTY / 北交所不重投。
- **北交所（`bj*`）边界透明化**：`--fetch-list` 会把 348 只北交所写进 `universe.csv`，
  但 TDX 协议层取不到（`E3040`）。
  - `--doctor` 把它们单列「协议不支持」，**不再当缺口**（此前会假报 348 个缺口）；
  - `--include-class bse` 打印显式告警（数量 + `E3040` + 建议 `--exclude-class bse`），
    不再静默必败；
  - 协议不支持标的的 SKIP **不再污染 `state.failed`**（避免永久累积）。
- **接口文档补上 K 线契约**：`docs/api/interfaces.md` 的两处 `bars` 条目新增
  「返回按 `datetime` 升序；`count` 是**上限**，上市时间不足时实际返回更少（短页
  即止，不补空行）」；`docs/cookbook/08_daily_history_sync.md` 全量口径更新为
  `MAX_WINDOW=10000`（页数上界 13），并新增「全市场全历史推荐运行流程」。

## 已知边界

- **分页光标按整页返回数推进**是有意为之：服务端返回的是「从 `offset` 起的连续块」，
  下一未读位置恒为 `offset + len(raw_rows)`；重复行只说明锚点漂了，不改变这条算术。
  按去重后的条数推进会倒退重读——已在 `_mixin.py` 就地留注释并把判据写进测试。
- **北交所真·全量仍不可得**：协议层硬拒（`market=2` 未验证）。要落 `bj*` 需引入
  非 TDX 数据源（akshare / 新浪），脚本暂不支持；现有行为是"能落的全落、落不了的
  明确告知"。
- `MAX_WINDOW=10000` 覆盖到 1990-12-19 起的全部 A 股日线；若未来出现更早历史或
  科创板新股逐日累积，余量按每年约 244 根递减，2032 年前无需再调。
