# v1.4.0 发布说明

## 一句话

把「落盘 → 读回」这条经典场景的**另一半**补上：`atst.output` 新增 `from_csv`
（`to_csv` 的对称读回面，零依赖）；同一轮把同步脚本里两处「事实源口径写歪」的
问题根治——**断点取数决策只信磁盘**、**扁平旧文件迁移后收走幽灵副本**，并给
`--doctor` 的空文件分支补上修复指引。

## Added

- **`atst.output.from_csv`**（``from_csv(path, *, columns=None)``）：`to_csv` 的对称面。
  写出面此前有 5 个写手（`write` / `to_dataframe` / `to_parquet` / `to_csv` /
  `to_duckdb`）、读回只有 parquet 一条——「导出给 Excel / 人工过目 → 加工 →
  读回程序」这条场景只完成一半，下游迟早每家自己写一行 `csv.DictReader`。
  - 零依赖（标准库 `csv`），带不带 BOM 都认（`utf-8-sig` 解码对两者都成立）；
  - **CSV 没有类型**：读回全 `str`，不做隐式数值推断——`"0012"` 变 `12` 是
    数据破坏不是便利；日期列不解析成时间对象（与 `from_parquet` 相反，按
    字符串比日期的调用方在这边反而省事）；
  - `columns=` 只取其中存在的列，缺列不出现（不填 `None`）；
  - 路径不存在抛 `FileNotFoundError`（不是"空结果"），与 `from_parquet` 同一口径。
- **`--doctor` 空文件分支给出修复指引**：缺口分支原有「下一步」提示，空文件
  此前只报数。现在同样指路（重跑增量命令；补完整历史加 `--full`）。

## Fixed

- **断点取数决策收敛到唯一事实源（磁盘）**。`_resume_bar_count` 原先
  `state.last_date` 优先于磁盘——与模块文档「断点第一事实源是磁盘」口径相反。
  真实后果：文件被清成 0 行（体检里的「空文件」）而 state 还记着旧日期时，
  修复只拉 `lookback + RESUME_OVERLAP` 的小窗口，**历史窗口静默缩水**且无提示。
  现在 `state.last_date` 不参与取数决策：写盘失败时断点不更新，state 只会比
  磁盘旧，砍掉它不丢任何真证据；`_last_date_on_disk` 在调用点本来就每只都读，
  state 从来不是加速，只是 `--doctor` 的对照副本。实网验证：清空
  `sh000003.parquet` 后增量修复拉回铺底窗口 320 行（而非小窗口续拉）。
- **扁平旧文件迁移收尾**。读旧扁平 `day/*.parquet`、写类别目录是一次迁移，
  但写成功后扁平那份永远留在盘上（`_path_of` nested 优先，它不会再被读）——
  幽灵副本占磁盘、迷惑翻目录的人。现在迁移写成功即收走扁平副本；删不掉只算
  外观问题，不碍同步。
- **`docs/releases/v1.3.0.md` 实测读数修正**：全市场代码表权威总数是 **8733**
  （`stock` 5223 / `bse` 348 / `bshare` 78 / `etf` 1819 / `lof` 355 / `bond`
  356 / `index` 554，与分项和吻合）；"8385 / 22 s"是仓库存量旧格式表（无表头
  两列）的读数，两套数字混写在了一行。

## 已知边界

- `from_csv` 不做类型推断是有意为之；要数值显式转。要保类型用 parquet。
- 断点取数只信磁盘后，`state.json` 的 `last_date` 不再影响拉多少根——它仍然
  会随每轮成功同步更新，供 `--doctor` 摊开比对。
- 东财 clist `fs` 真机校准后从 `TBD_SOURCES` 登记（沿 v1.3.0）。
