# v1.3.0 发布说明

> tag：`v1.3.0` · 版本单一事实源：[`atst/_version.py`](../../atst/_version.py) = `1.3.0` ·
> 上一版本：[v1.2.2](v1.2.2.md)

## 一句话

新增**「按类别取全部标的」**这条场景链路：`atst.universe` 按
**代码表 → 新浪节点 → tdx 段表** 三级降级供给七类标的（A 股 / 北交所 / ETF / LOF /
可转债 / 指数 / B 股），并把它接到 CLI（`atst universe`）、HTTP
（`/v13/universe`、`/v13/universe/{kind}`）与同步脚本（`--fetch-list`）三张面上；
同一轮把同步链路的验收读数 `--doctor` 补上，并给输出层补上写出的**对称读回面**
`from_parquet`——"同步落盘 → 读回研究"这才是一条完整链路。

## Added

### `atst.universe`：七类标的的清单编排层

`0x044D SECURITY_LIST` 实测已 offline（`E3035` 多主站无响应），"有哪些标的"这条
需求原先没有入口。新模块**不重写 HTTP 层**，只做编排：

| 源 | 复用什么 | 量级 | 覆盖 |
|----|---------|------|------|
| `table` | 读 `<root>/universe.csv`（同步脚本产出） | 毫秒 | 表里有什么就有什么 |
| `sina` | `SinaSource.fetch_all`（分页 + 并发 + 令牌桶都是现成的） | 秒级 | `stock` / `bse` / `bshare`，带名称 |
| `tdx` | `TdxClient.bars(count=1)` 逐只探 | 分钟级 | 七类全覆盖 |

- **七类口径**：`stock`（含新开的 `sz302` 段）/ `bse`（只剩 `bj920`）/ `etf` /
  `lof` / `bond` / `index`（走 `0x052D` 指数位）/ `bshare`。类别决定落盘目录、
  决定走不走指数位，与同步脚本共用同一份表（`atst.universe._classes.ASSET_CLASSES`）。
- **公开面**：`list_universe` / `list_all_universe` / `universe_report` /
  `class_of` / `classify` / `from_table` / `ASSET_CLASSES` / `TBD_SOURCES` …
- **缺口如实登记**：东财 clist 的 `fs` 映射（`b:MK0021` 一类）尚未真机校准，
  因此**没有**被写进源表，而是记在 `TBD_SOURCES` 里等校准后再登记——没校准过的
  `fs` 写进代码表就是一锅"静默返回空"的雷。

### CLI：`atst universe`

```bash
atst universe --list-class          # 七类 + 新浪节点参考表（不联网）
atst universe etf --dry-run         # 只报各源代价，不真拉 tdx
atst universe etf --show 5          # 打印前 5 条
atst universe stock --json          # 机器可读
```

`--dry-run` 与 `--json` 可以叠加（`--dry-run --json` 给结构化报告）；`--dry-run`
**不会**去跑 tdx 段表探测——那正是它要避开的代价。

### HTTP：`/v13/universe` 与 `/v13/universe/{kind}`

```bash
curl 'http://127.0.0.1:8000/v13/universe'              # 类别表（静态）
curl 'http://127.0.0.1:8000/v13/universe/etf'          # 本地代码表里的全部 ETF
curl 'http://127.0.0.1:8000/v13/universe/all?limit=50' # 七类各取前 50 条
```

HTTP 面**只读本地代码表**、不提供 `source` 旋钮：新浪那一级是外呼、tdx 那一级是
分钟级批作业，把任一级塞进请求路径都会占住网关（超时与重试语义也全乱）。要刷新
清单就跑批任务 `--fetch-list`，网关只负责把已落好的表发出去；表不存在时回
`200` + `count: 0` + `hint`——"还没跑过同步"是部署常态，不是请求错误。

### 同步脚本：`--fetch-list` 与 `--doctor`

- `--fetch-list [--fetch-class etf,bond] [--fetch-source auto|table|sina|tdx]
  [--fetch-dry-run]`：秒级把七类清单写进 `<root>/universe.csv`（三列
  `代码,类别,名称`），供随后的增量同步直接消费。
- `--doctor [--json]`：**不联网**体检四类坏法——**缺口**（代码表里有、`data/day/`
  里没有）/ **空文件**（parquet 在但 0 行）/ **落伍**（最后日期落后于全市场最新
  交易日）/ **断点漂移**（`state.json` 与磁盘不符）。有缺口 / 空文件时退出码 `2`；
  落伍与断点漂移只报不抬码（它们要"知道"，不是要"修"）。

### `atst.output.from_parquet`：输出层补上对称的读回面

输出层有 4 个写手（`write` / `to_dataframe` / `to_parquet` / `to_csv` / `to_duckdb`）
却**没有任何读回入口**时，"同步落盘 → 读回研究"这条经典场景只完成了一半：
`scripts/sync_daily_history.py` 落下的 `data/day/<类别>/<代码>.parquet` 读回来还得
自己知道 pyarrow 怎么用、日期列叫什么。

```python
from atst.output import from_parquet

rows = from_parquet("data/day/stock/sh600519.parquet")            # list[dict]
dates = from_parquet("data/day/stock/sh600519.parquet", columns=["date"])
```

两条边界刻意做成**报错而不是空列表**：缺 `pyarrow` 抛
`DependencyMissingError`、路径不存在抛 `FileNotFoundError`——"没装依赖"、
"路径打错"、"文件是空的"是三件不同的事，混成一个 `[]` 会让人查错方向。
另注：`to_parquet` 经 DataFrame 写，`datetime`/`date` 列读回来是时间对象而不是
原字符串，按 `YYYY-MM-DD` 比日期的调用方要自己归一一次（脚本侧
`_last_date_on_disk` 就是这么做的）。

## Fixed

- **`--fetch-list` 曾静默漏掉北交所**：类别候选面原先取自脚本的扫描顺序表
  （`_SCAN_ORDER` 里没有 `bse`——客户端 `E3040` 探不出来），兜底分支永不触发。
  现在候选面锚定 `atst.universe.ASSET_CLASSES`，北交所由新浪 `hs_a` 里的 `bj*`
  拆出（实测 348 只）。
- **段表探测的候选展开写错**：`segment_candidates` 把 `sh600` 截成 `sh`、产出
  `sh000…sh999`；`--dry-run` 从不真探，所以一直没暴露。现在 `sh600` →
  `sh600000…sh600999`。
- **老格式单列代码表**被整表当成同一个类别交出（要 ETF 却拿到 A 股）；**显式源
  拿空**被静默返回空列表（"为什么 ETF 是空的"变成没有线索的谜题）——现在前者
  按前缀现判类别，后者抛 `LookupError`，报告层把它摊成表格里的一格。
- **`--scan` 与 `--fetch-list` 落的代码表形状不一致**（前者两列无表头、后者三列有
  表头）：两个生产者各写各的格式，下游迟早长出"先看是两列还是三列"的分支。现在
  两者共用同一个写手。
- **`atst universe --dry-run` 会真跑 tdx 探测**：`--dry-run` 的全部意义是"先看代价"，
  让它跑就等于"先付代价"。现在停在 tdx 前只报候选量（段数 × 1000）。
- **`--dry-run --json` 被静默降级成人读文本**。

### 发布前复查（第 3 轮）又清掉的一批

这一轮的问题都不是"跑错了"，而是**判据写歪了、于是保护一直是空的**：

- **北交所的判据恒为假**：`classify` 里写的是 `token[:3] == "bj"`，而
  `"bj920000"[:3]` 是 `"bj9"`——这条保护只剩 `bj` 两个字面量能触发，`bse` 实际
  全靠段表里的 `bj920` 兜着。北交所真开新段（430/830）那天，那些代码会被静默判成
  `stock` 写进 `day/stock/`。改 `startswith("bj")` 后判据才真的成立。
- **另一条判据是死分支**：`token[2:4] in ("00", "01")` 与 `token[:3] in ("sh9", "sz2")`
  互斥（`token[2]` 恒为 `9`/`2`），永远进不去；B 股本就由段表（`sh900`/`sz200`）
  覆盖，这份重抄的判据直接删掉。
- **tdx 探测结果顺序泄漏了线程完成序**：`as_completed` 的顺序随并发负载与网络
  抖动变，同一份数据两次可能出两份顺序——CLI 输出、快照判据、"两条取数链路结果
  应当一致"的比较都会变成偶发红。改为按候选顺序（段 × 流水号）出。
- **`limit` 在两条路径上含义不同**：`all` 那支对代码表 / 新浪拿到的行根本不截
  （只有 tdx 探测接 `limit`），`limit=0` 还被当成"不限"（先拉全市场再原样返回）。
  现在统一到一处截断，`limit=0` 就是"一条都不要"且不触碰任何取数源。
- **同一个类别判定在脚本里又实现了一遍**：脚本自己遍历那张按 `_SCAN_ORDER` 建、
  **没有 `bse`** 的 `CLASS_SEGMENTS`，于是 `bj920000` 一路落到 `return "stock"`。
  现在脚本只留转发口，判定锚定 `atst.universe`（判据双向比对两者答案）。
- **`INDEX_PREFIXES` 把"index 恰好排在扫描顺序第一位"当成事实**
  （`CLASS_SEGMENTS[0][1]`）：哪天为大段调 `_SCAN_ORDER`，这里会静默换成别人的段。
  改按类别名取。
- CLI `atst universe` 的 `directory` 列写 `row.kind`（抄了一遍"目录恰好同名"的
  事实），改走 `class_of_directory`。
- HTTP `/v13/universe/{kind}` 的 docstring 写了"可以放心缓存与并发"，被
  `test_production_prose_never_claims_a_data_cache` 拦下——缓存层第 18 步已物理
  删除，注释不许再替它说话。改述为"结果完全确定"，门禁不动。
- `docs/ARCHITECTURE.md` 的 `cli/`（31 子命令）与 `/v13/`（10 路由）两处陈旧口径
  同步为 32 / 12；包 docstring 的 CLI 子命令数同步。

## 已知边界

- **HTTP 面不提供联网取清单**（见上）：这是刻意的分工，不是缺口。
- 东财 clist 作为第二源仍待真机校准（`TBD_SOURCES` 已登记）；本轮实测 push2
  全站处于 IP 级软限流。
- `bse` 只能从新浪 `hs_a` 里按前缀拆（tdx 协议层拒 `bj*`，`E3040`），因此
  `--scan` 拿不到北交所——要北交所用 `--fetch-list --fetch-class bse`。
- 北交所旧段 `bj430/830/870` 实测为空，段表只留 `bj920`（**探测**用）；但类别
  判定走 `bj` 前缀，所以哪天旧段重新有货，"探不探"与"算哪类"是两件独立的事，
  扩段不会再把新段静默算成 `stock`。
- 交易日历的 2026 年数据仍是估算值（`estimated=True`），与本版新增面无关。
- 本包仍**不在 PyPI 上**：上传是显式 opt-in（需仓库变量 `PUBLIC_RELEASE=true`）。
