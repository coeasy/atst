## 一句话

K 线这条路有两个洞：**回来 0 根时不说为什么**，以及**不存在的代码会把乱码当 K 线返回**。
两条都在 v1.6.1 补上，且都按"结果自带告警 + `strict` 可升级为失败"的老规矩接进
`ResultMeta.warnings`，没有引入新的返回形状。

## Fixed

### 1. `bars` 回来 0 根时不再沉默

分页游标是"从最新往回数 `count` 根"，所以**历史耗尽只会表现为短页**——请求 320 根回来 87 根。
"0 根"因此永远是一个需要解释的事实，而此前只有 tdx 那条路解释了它
（`bars_empty_first_page`，判据要读服务端当次声明的记录数）。其余后端——尤其 Web 源对不支持的
标的/周期直接回空数组——一个字都不说。

三种完全不同的处境，在结果里长得一模一样：`ok` + 0 行 + 零告警。

实测（2026-10-30 收盘后）：

```text
bars("bj430047", provider="auto")  ->  n=0  prov=tencent  warnings=()        # 旧
bars("bj430047", provider="auto")  ->  n=0  prov=tencent  warnings=(BARS_EMPTY_RESULT,)  # 新
```

新判据 `bars_empty_result` 放在**执行器出口**，因此与后端无关，也不必让每个 Web 适配器各记一遍。
去重规则写在 `atst/diagnostics.py` 的 `EMPTY_EXPLAINED_CODES`：`bars_empty_first_page`（tdx 空桩，
带声明数）与 `bars_page_unusable`（整页丢弃）已经解释过同一件事时，不再补一条泛泛的"0 根"。

### 2. 不存在的代码不再返回乱码 K 线

```text
bars("sh999999", period="day", count=5)
# 旧：5 根，datetime 是 8047-92-78 / 334231-62-94，只有一条 field_out_of_domain 告警
# 新：0 根，告警 field_out_of_domain + bars_page_unusable
```

主站对不存在的代码回的是缓冲区里别的标的，页内字节数对得上，所以解码层自己不会报错；
值域尺子量出来是越域，但此前只发一条告警就把行交出去了——下游会把它当真。

新判据：**一页里超过半数记录越域 → 整页丢弃**，并发 `bars_page_unusable`。门槛取严格多数
而不是"全部"，因为真实错位页的头一根常常恰好还对得上——`sh999999` 实测就是 1 根干净 + 4 根越域；
指数位走反时也是"第 1 根对、其后整体错位"这同一个形状。按"全部越域"判会漏网，按"有一根越域"判
又会把局部瑕疵整页连坐。

## Changed

- `docs/providers/tdx.md` 新增「它是默认源，而且是唯一的默认源」：缺省解析落在
  `QuerySpec.normalized()`、港美/北交所边界、无跨源兜底、`bars` 不做复权。
- `docs/FAQ.md` 新增「取数与选源」两问，含"0 根到底是什么意思"的三条告警对照表。
- `docs/api/interfaces.md` 的 `Client.bars` 一行补默认源与空结果口径。
- `docs/errors.md` 的类别表新增 `bars_empty_result` / `bars_page_unusable` 两行，与枚举双向对齐。

## 升级注意

- `strict=True` 的调用方：0 根现在会**失败**（`TruncatedDataError`，E4050）而不是返回空列表。
  这是既有语义（strict 对任意瑕疵生效）的自然延伸，但对"用空列表判断没有数据"的代码是一次行为变化。
- 依赖 `field_out_of_domain` 之后仍能拿到行的调用方：错位页现在返回空。判断"这一页是否被丢弃"
  请查 `bars_page_unusable`。
- 默认 Provider、协议布局、账本状态（`tier` / `verified`）均未改动。
