# v1.2.2 发布说明

> tag：`v1.2.2` · 版本单一事实源：[`atst/_version.py`](../../atst/_version.py) = `1.2.2` ·
> 上一版本：[v1.2.1](v1.2.1.md)

## 一句话

修复 v1.2.1 发布流水线失败的根因：**代码把市场时刻绑在了运行机器的本地时区上**，
本地（UTC+8）全绿、CI（UTC）两红。时间戳与交易时段统一按市场时区 `Asia/Shanghai`
渲染，结果只取决于输入值。

## CI 失败现象与根因

`wheels.yml` 的首个门禁 job（`Verify release source and deterministic gates`）红，
后续 7 个 job 全部 skipped：

```
FAILED tests/web/test_v6_new_sources.py::test_cninfo_parses_a_share_announcements
  assert first["publish_time"].startswith("2026-09-30")
  +  where False = '2026-09-29 16:00:00'.startswith('2026-09-30')
FAILED tests/web/test_v6_new_sources.py::test_wallstreet_parses_lives
  assert first["publish_time"].startswith("2026-10-02")
  +  where False = '2026-10-01 16:07:02'.startswith('2026-10-02')
= 2 failed, 4304 passed, 6 skipped in 215.58s
```

两个用例读的是 `tests/golden/v6/*.json` **离线样本**（不打网络），却随机器时区漂移。
根因在解析层——下面这行修复前的代码里，两个适配器都拿 `localtime` 渲染
`publish_time`（`localtime` 是标准库 `time` 模块的函数，作用是取**运行机器本地时区**）：

```python
# 修复前：cninfo/adapters.py + wallstreet/adapters.py
return time.strftime("%Y-%m-%d %H:%M:%S", time.localtime(ms / 1000))
```

`localtime` 取**运行机器的本地时区**。golden 样本在北京时间（UTC+8）抓取，本机解析得
`2026-09-30 00:00:00`（断言成立）；GitHub runner 是 UTC，同一份样本解析成
`2026-09-29 16:00:00`——偏 8 小时，断言必红。

**这不是测试脆弱，是数据缺陷**：A 股公告/快讯的发布时刻是市场事实，把 UTC+8 机器上
正确的值在 UTC 机器上渲染错，意味着任何部署在非中国时区的用户都会拿到错 8 小时的
`publish_time`。

## Fixed

- 新增 `atst.domain.calendar` 的时区工具（§23「交易日历与时区」同属一处，单一事实源）：
  - `MARKET_TZ_NAME = "Asia/Shanghai"`、`market_tz()`（缺 tzdata 回退固定 +08:00，
    不在模块顶层建 `ZoneInfo`——Windows 纯 pip 环境会炸 import）、
    `to_market_tz()`、`market_now()`、`market_timestamp(value, unit="s"|"ms")`。
- `cninfo` / `wallstreet` 两个解析器改走 `market_timestamp()`；`atst/web/normalize.py`
  只做转出别名（`from ..domain.calendar import MARKET_TZ_NAME, market_timestamp`），
  解析器不再各自造轮子。
- **同类隐患一并修掉**：`ratelimit` 模块的 `session_state` 此前用 naive
  `datetime.now()` 判断交易时段，CI（UTC）会把北京时间 09:45 的连续交易时段判成
  `CLOSED`，限流分档随部署环境漂移。现默认取 `market_now()`；传入 aware 时间则统一
  换算到市场时区再比较。

## Tests

- `tests/web/test_normalize.py::TestMarketTimestamp`：真机样本 epoch
  （`1790697600` == `2026-09-29T16:00:00Z` == `2026-09-30 00:00:00 +08:00`）渲染、
  **四时区（UTC / Asia-Shanghai / America-New_York / Pacific-Kiritimati）结果一致**、
  非数值与 `bool` 拒绝。
- `tests/transport/test_ratelimit.py::TestSessionStateUsesMarketTimezone`：aware UTC
  输入与 naive 本地输入判出同一交易状态；默认 now 走市场时区。
