## 2. Migrated legacy capability families

The v13 catalog now covers the business abilities previously reachable through the retired `UnifiedQuoteAPI`, including:

- finance, corporate actions and adjustment;
- F10;
- blocks, sectors, indexes, rankings, auction and volume-price;
- funds, fund companies and fund managers;
- bonds, futures, options, commodities and extended markets;
- valuations, statements, shareholder/governance and ESG datasets;
- macro, IPO and northbound datasets;
- search, suggest and iWencai;
- news, announcements, research reports and research visits;
- FX/rates;
- local-day synchronization;
- web supplemental market/history/minute capabilities.

`tests/runtime/test_legacy_capability_migration_v13.py` is the migration gate: the historical business capability contract must be a subset of `MIGRATED_CAPABILITIES`, every migrated Registry entry must have a DirectBinding, and representative finance/fund/derivative/news/F10 abilities must compile through QueryPlanner.

## 3. Provider identity rules

- `web` is not a Provider and remains rejected.
- `local_vipdoc` is a Provider, not a TDX channel.
- `derived` is explicit provenance for aggregate/composite execution; it is not hidden fallback.
- known single-source abilities use their actual Provider.
- helpers that internally select/compose sources use `derived` rather than publishing false Eastmoney/Sina/Tencent provenance.
- cross-Provider fallback remains exclusively `FallbackPolicy -> ProviderOrchestrator`.
- one Registry row without DirectBinding is a gate failure.
- one DirectBinding outside the Registry is an architecture error.

## 4. Public access model

All migrated capabilities use the same execution chain:

```text
Client.call / AsyncClient.call
  -> QuerySpec
  -> QueryPlanner
  -> UnifiedRuntime
  -> exact DirectBinding
  -> Provider implementation
  -> QueryResult / Provenance
```

Same-name dynamic Client methods are provided for migrated abilities, e.g. `client.fund_rank(...)`, `client.balance_sheet(...)`, `client.options_snapshot(...)`, while `Client.call("...")` is the canonical generic surface.

Transport parity is provided by:

- HTTP `POST /v13/query/{capability}` and `GET /v13/capabilities`;
- WS JSON-RPC `query` and `runtime.capabilities`;
- MCP `query_capability`;
- CLI `tstdx query` and `tstdx capabilities`.

Tier-A keeps dedicated ergonomic endpoints/tools in addition to the generic capability path.
