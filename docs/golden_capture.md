# Golden 采集清单与翻牌流程（v2 / F3）

> 目标：把 `verified=False` 的命令**逐条**用真机样本锁住布局，翻成 `verified=True`。
> 本文只交付**清单与流程**；翻牌按样本到位滚动进行，不阻塞 v2 发布。
>
> 样本即契约：一个样本 = `payload.bin`（解压后的原始字节）+ `meta.yaml`（主机、请求体、
> sha256、抓取时间）。先校验哈希再跑解析，避免"样本被手改过还全绿"。

## 1. 采集清单

采集器：`python -m atst.tools.capture`（见 [capture.py](../atst/tools/capture.py)）。
样本落盘：`tests/golden/<family>/<command>_<tag>/<yyyymmdd-HHMMSS>/`。

### 1.1 7709 核心族（`--plan core`）

`--plan core` 已内置沪深**双边**变体（E8 修复后的计划），每命令每市场取 **1** 个样本：

| 命令 | 名称 | 市场 | 样本（tag） | 样本数 |
|---|---|---|---|---|
| `0x044E` | 证券数量 | 0 / 1 | `market0` / `market1` | 2 |
| `0x000F` | 除权除息 | 1 | `600000`（另建议 `600519`、`601398` 补充） | 1（建议 3） |
| `0x000F` | 除权除息 | 0 | `000001`（另建议 `000002`、`002415` 补充） | 1（建议 3） |
| `0x0010` | 财务基础信息 | 1 | `600000`（另建议 `600519`、`601398` 补充） | 1（建议 3） |
| `0x0010` | 财务基础信息 | 0 | `000001`（另建议 `000002`、`002415` 补充） | 1（建议 3） |
| `0x0537` | 分时图 | 0 / 1 | `600000` / `000001` | 2 |
| `0x0FC5` | 逐笔成交 | 0 / 1 | `600000` / `000001` | 2 |

> 说明：`0x000F`（29B 股本变迁记录）与 `0x0010`（143B 财务记录）是**布局最容易漂移**的
> 两条，建议每个市场至少 3 只不同板块的样本（主板 / 创业板 / 中小盘），共 6 个/命令。

MAC 命令不是 `--plan` 内置计划，需按单命令采集（每命令 1 个样本，市场 0 / 1 各一）：

## 2. 翻牌流程（`verified=False → True`）

1. **采集**（交易时段外，需 `--i-understand-the-legal-boundary`）：
   ```powershell
   python -m atst.tools.capture --plan core --host 218.75.126.9:7709 --out tests/golden
   ```
   每个样本目录必须含 `payload.bin` / `meta.yaml`；`meta.yaml` 的 `sha256` 与 payload 一致。
2. **本地回放**：`python -m pytest tests/golden -q`，确认新样本被解析器消费且断言绿。
3. **翻牌**：在 `atst/protocol/commands.py` 对应 `Command` 上把 `verified` 置 `True`
   （只翻**本样本覆盖到的命令 × 市场**，未覆盖市场继续 `False`）。
4. **同步文档**：`make docs-gen` 重新生成 `docs/generated/registry.md` 与
   `docs/tdx_status.md` 的数字格；`git diff` 应只出现该命令的 `verified` 单元格变化。
5. **提交**：样本 + 账本 + 生成物同一个 commit；commit message 注明
   `golden: 0xXXXX market=<m> verified=True`。

## 3. 纪律

- 采集前打印并确认法律边界声明；交易时段采集必须显式 `--allow-trading-hours`（仅维护者）。
- 不抄录任何开源项目的样本；样本一律由本工具连真实主站抓取。
- 单命令失败只记 warning，不中断整体采集；失败样本**不入库**、不翻牌。
- 翻牌后若解析器回归失败，先回滚 `verified` 再查样本，不允许"改样本迁就代码"。
